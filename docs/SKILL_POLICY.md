# Specialist skill system

## Hierarchical specialist library (selected architecture B)

A skill declares its scope, inputs, outputs, required tools, failure conditions, safe boundaries, and validation method. A department coordinates skills without duplicating core execution code.

Shipped skills: asset-inspection, asset-conversion, mesh-repair and procedural-primitives.

## Dynamic skill generation (selected architecture C; not implemented in v0.0.1)

New procedures generated by an LLM are untrusted proposals. They must not automatically execute Python, fetch secrets, add dependencies, or obtain stronger permissions by their name or placement.

Candidate lifecycle: identify capability gap; search existing skills; define a proposed procedure; run isolated tests on synthetic inputs; perform negative-path and portability reviews; propose a reviewable candidate; promote only after approval and exact-code validation.

Trust states: experimental, temporary, candidate, approved. A single success does not justify promotion. No automated promotion is provided in v0.0.1.

Names use a stable prefix such as blender-agent.asset.inspection and blender-agent.model.primitives. These are identifiers, not remote execution endpoints.
